# 大学生未来规划系统

大学生未来规划系统 —— Vue 3 + Flask + MySQL 前后端分离项目（第一周目标：项目架构、注册、登录、MySQL 用户存储、登录后首页、个人中心）。

## 技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| 前端 | Vue 3 + Vite | 页面、表单、路由（vue-router） |
| 后端 | Flask + flask-sqlalchemy + pymysql | 提供注册/登录等接口 |
| 数据库 | MySQL 8.4 | 存用户数据 |

## 接口约定（★ 最重要的约定，D1 结束前三人共同确认，此后谁都不许擅自修改）

后端接口统一返回这种 JSON 格式：

```json
{ "code": 0, "msg": "成功", "data": {} }
```

### 接口清单

| 接口 | 方法 | 前端发什么 | 后端返回什么 |
|------|------|-----------|-------------|
| `/api/health` | GET | 无 | `{code:0, data:{service, status}}` |
| `/api/register` | POST | `{username, password, name, major, grade}` | `{code:0, msg:"注册成功", data:{token}}` |
| `/api/login` | POST | `{username, password}` | `{code:0, msg:"登录成功", data:{token}}` |
| `/api/me` | GET | 请求头带 token | `{code:0, data:{username, name, major, grade}}` |
| `/api/me` | PUT | 请求头带 token + `{name, major, grade}` | `{code:0, msg:"保存成功", data:{username, name, major, grade}}` |

### 错误码约定

| code | 含义 |
|------|------|
| 1001 | 参数格式不对（如用户名不符合规则） |
| 1002 | 密码太短 |
| 1003 | 用户名已存在 |
| 1004 | 用户名或密码错误 |
| 401 | 未登录 / 登录过期 |
| 5000 | 服务器内部错误（全局兜底，HTTP 状态码 500；前端拦截器会直接显示 msg） |

### 其他约定

- 字段名一律用小写 + 下划线风格（`username`，禁止 `userName`）
- 后端端口固定 `5000`，前端端口固定 `5173`，前端请求一律走 `http://localhost:5000/api/...`
- `token` 由后端在注册/登录成功时生成，前端存起来，之后每次请求 `/api/me` 等接口时放在请求头里带来

> ✅ 当前进度：以上四个接口后端均已实现并通过实测（2026-09-26）。
>
> ➕ 补充（2026-09-29）：`PUT /api/me` 修改个人资料，为前端个人中心「保存修改」新增。
> - 只允许改 `name / major / grade`，**不允许改 username 和密码**
> - 未登录 → 401；`name` 为空 → 1001
> - 返回更新后的完整资料，前端可直接刷新页面显示

## 数据库说明

| 项 | 内容 |
|----|------|
| 正式方案 | MySQL 8.x，库名 `futurepath`，表名 `users` |
| 建表脚本 | `backend/init.sql`（**表结构以这个文件为准**） |
| 后端模型 | `backend/app/models/user.py`（SQLAlchemy） |
| 开发期兜底 | 未配置 `.env` 时后端自动使用 SQLite（`backend/instance/dev.db`） |

**为什么要兜底**：`.env` 不会提交到 Git（里面的密码不能进仓库），
组员 clone 下来没有配置文件。用 SQLite 兜底，任何人 clone 完都能直接跑起来。

**两处表结构必须保持一致**，改任何一处都要同步另一处：

| 字段 | MySQL (`init.sql`) | SQLAlchemy (`user.py`) |
|------|--------------------|------------------------|
| id | INT PK AUTO_INCREMENT | Integer, primary_key |
| username | VARCHAR(20) UNIQUE | String(20), unique, index |
| password_hash | VARCHAR(256) | String(256) |
| name | VARCHAR(64) | String(64) |
| major | VARCHAR(64) NOT NULL | String(64), NOT NULL |
| grade | VARCHAR(16) NOT NULL | String(16), NOT NULL |
| created_at | DATETIME NULL | DateTime，由后端写入 UTC |

> 想切到 MySQL：在 `backend/` 下建 `.env`，写入
> `DATABASE_URL=mysql+pymysql://root:你的密码@localhost:3306/futurepath?charset=utf8mb4`
> 然后重启后端。

## 本地怎么跑起来

### 前置：装依赖

```bash
# 后端
cd backend
pip install -r requirements.txt

# 前端
cd frontend
npm install
```

### ★ 关键一步：建前端环境文件

`frontend` 目录下新建文件 `.env`，内容一行：

```
VITE_USE_MOCK=false
```

**为什么必须建**：不建的话前端默认走 Mock 假数据 —— 页面看着能注册成功，但数据库里什么都没有。
改完**必须重启 `npm run dev`** 才生效（vite 不热更新配置文件）。

### 启动（两个终端）

```bash
# 终端 1：后端
cd backend
python run.py                 # 看到 Running on http://127.0.0.1:5000

# 终端 2：前端
cd frontend
npm run dev                   # 看到 Local: http://localhost:5173/
```

浏览器打开 <http://localhost:5173>，F12 控制台应显示：

```
[env] 当前模式：真实接口 /api
```

### 自检：验证联调是否正常

**三个终端都开着**，再开一个：

```bash
cd frontend
node tools/check-live.cjs
```

25 项全过 = 前后端联调没有断点。这个脚本会真注册一个带时间戳的账号，
所以只要能显示出来，就一定是真后端给的数据，不存在“mock 蒙对了”的情况。
