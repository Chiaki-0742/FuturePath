# 大学生未来规划系统

大学生未来规划系统 —— Vue 3 + Flask + MySQL 前后端分离项目（第一周目标：项目架构、注册、登录、MySQL 用户存储、登录后首页、个人中心）。

## 技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| 前端 | Vue 3 + Vite | 页面、表单、路由（vue-router） |
| 后端 | Flask + flask-sqlalchemy + pymysql | 提供注册/登录等接口 |
| 数据库 | MySQL 8.4 | 存用户数据 |

## 三人分工

协作原则：**每个人负责一条线，边界清晰，互不改对方文件**。接口联调前先约定好数据格式。

### 同学 A —— 后端工程师（backend/）
- 负责：`backend/` 目录全部代码
- 任务：Python 虚拟环境、Flask 安装、数据库连接配置、注册接口 `/api/register`、登录接口 `/api/login`
- 产出标准：用 Postman/curl 调接口能返回正确 JSON

### 同学 B —— 前端工程师（frontend/）
- 负责：`frontend/` 目录全部代码
- 任务：Vue 3 脚手架搭建、注册页面、登录页面、登录后首页、个人中心页面
- 产出标准：页面上填表单能发出请求、展示返回结果

### 同学 C —— 队长 / 数据库与联调（全局）
- 负责：MySQL 数据库、Git 仓库管理、进度跟踪
- 任务：建库建表（users 表）、定接口文档（见下）、合并大家的代码、每天汇总进度
- 产出标准：数据库可连、接口文档齐全、代码及时合并不冲突

> 如果三人水平接近，也可以两人主写代码、一人主做测试和文档。关键不是头衔，是**每人每天有明确产出**。

## 接口约定（★ 最重要的约定，D1 结束前三人共同确认，此后谁都不许擅自修改）

后端接口统一返回这种 JSON 格式：

```json
{ "code": 0, "msg": "成功", "data": {} }
```

### 接口清单

| 接口 | 方法 | 前端发什么 | 后端返回什么 |
|------|------|-----------|-------------|
| `/api/health` | GET | 无 | `{code:0, data:{service, status}}` |
| `/api/register` | POST | `{username, password, name, major, grade}` | `{code:0, msg:"注册成功", data:{token}}` |
| `/api/login` | POST | `{username, password}` | `{code:0, msg:"登录成功", data:{token}}` |
| `/api/me` | GET | 请求头带 token | `{code:0, data:{username, name, major, grade}}` |

### 错误码约定

| code | 含义 |
|------|------|
| 1001 | 参数格式不对（如用户名不符合规则） |
| 1002 | 密码太短 |
| 1003 | 用户名已存在 |
| 1004 | 用户名或密码错误 |
| 401 | 未登录 / 登录过期 |

### 其他约定

- 字段名一律用小写 + 下划线风格（`username`，禁止 `userName`）
- 后端端口固定 `5000`，前端端口固定 `5173`，前端请求一律走 `http://localhost:5000/api/...`
- `token` 由后端在注册/登录成功时生成，前端存起来，之后每次请求 `/api/me` 等接口时放在请求头里带来

> ✅ 当前进度：以上四个接口后端均已实现并通过实测（2026-09-26）。

## 共享进度：Git 工作流

1. 同学 C 在 Gitee（国内快）或 GitHub 上建一个**私有仓库** `future-plan-system`
2. 同学 C 把本地仓库推送上去（`git remote add origin <仓库地址>` → `git push -u origin main`）
3. A、B 各自 `git clone` 仓库到本机
4. 日常流程（每人每天）：

```bash
git pull                      # 1. 开工前先拉最新代码
# ...写代码...
git add .
git commit -m "说明这次改了什么，如：完成注册接口"
git push                      # 3. 推送到远程
```

5. 规则：
   - **每人只改自己负责的目录**（A 只动 backend，B 只动 frontend，C 只动 docs/SQL/README），冲突基本不会发生
   - commit 信息用中文写清楚做了什么
   - 谁都不许直接改别人的文件，发现问题在群里说，由负责人自己改
