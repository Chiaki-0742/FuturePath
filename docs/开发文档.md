# 大学生未来规划系统

大学生未来规划系统 —— Vue 3 + Flask + MySQL 前后端分离项目（第一周目标：项目架构、注册、登录、MySQL 用户存储、登录后首页、个人中心）。

## 技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| 前端 | Vue 3 + Vite | 页面、表单、路由（vue-router） |
| 后端 | Flask + flask-sqlalchemy + pymysql | 提供注册/登录等接口 |
| 数据库 | MySQL 8.4 | 存用户数据 |

## 接口约定（★ 最重要的约定，D1 结束前三人共同确认，此后谁都不许擅自修改）

后端接口统一返回这种 JSON 格式：

```json
{ "code": 0, "msg": "成功", "data": {} }
```

### 接口清单

| 接口 | 方法 | 前端发什么 | 后端返回什么 |
|------|------|-----------|-------------|
| `/api/health` | GET | 无 | `{code:0, data:{service, status}}` |
| `/api/register` | POST | `{username, password, name, major, grade}` | `{code:0, msg:"注册成功", data:{token}}` |
| `/api/login` | POST | `{username, password}` | `{code:0, msg:"登录成功", data:{token}}` |
| `/api/me` | GET | 请求头带 token | `{code:0, data:{username, name, major, grade}}` |
| `/api/me` | PUT | 请求头带 token + `{name, major, grade}` | `{code:0, msg:"保存成功", data:{username, name, major, grade}}` |

### 错误码约定

| code | 含义 |
|------|------|
| 1001 | 参数格式不对（用户名不符合规则、必填项为空、字段超长） |
| 1002 | 密码长度不合规（需 6-64 位） |
| 1003 | 用户名已存在 |
| 1004 | 用户名或密码错误 |
| 401 | 未登录 / 登录过期 |
| 4040 | 接口路径不存在（HTTP 404；路由写错时返回 JSON 而不是 HTML 报错页） |
| 4050 | 请求方法不对（HTTP 405；比如该用 POST 却用了 GET） |
| 5000 | 服务器内部错误（全局兜底，HTTP 状态码 500；前端拦截器会直接显示 msg） |

### 字段校验规则（前后端必须保持一致）

| 字段 | 规则 | 超限返回 |
|------|------|----------|
| `username` | **3-20 位半角字母或数字**（正则 `^[a-zA-Z0-9]{3,20}$`）；**不允许中文、下划线、空格** | 1001 |
| `password` | 6-64 位（不做首尾空白裁剪，密码里的空格是有效字符） | 1002 |
| `name` | 必填，≤ 64 字符 | 1001 |
| `major` | 选填（空则存"未填写"），≤ 64 字符 | 1001 |
| `grade` | 选填（空则存"未填写"），≤ 16 字符 | 1001 |
| `extra_note`（问卷补充说明） | 选填，≤ 500 字符 | 1006 |
| `status`（问卷现状答案） | 必须是对象；序列化后 ≤ 2000 字符 | 1006 |
| `interest`（问卷想了解什么） | 必须是数组，最多 3 项；序列化后 ≤ 500 字符 | 1006 |

> ⚠️ 长度上限来自数据库列宽（`init.sql` 里的 `VARCHAR` / `TEXT`）。后端已提前拦下并返回
> JSON 错误提示；如果不拦，MySQL 严格模式会直接抛异常变成 500，前端拿到的是一整页
> HTML，只会显示"请求失败"，用户看不懂。
>
> 实测记录（2026-10-04）：`extra_note` 传 7 万字 → 修复前 HTTP 500 + `DataError 1406`；
> 修复后返回 `{code:1006, msg:"补充说明不能超过500字"}`。
> ⚠️ 规则以前端注册页为准（前端用同样的正则），后端做了**同样一份**校验 ——
> 因为前端可以被绕过（浏览器控制台、curl 都能直接调接口），安全相关的规则
> 不能只靠前端拦。

### 时间字段约定

所有 `created_at`（注册时间 / 填写时间 / 提问时间）统一走 `app/utils.py` 里的 `now()`，
即**本机时间**。

- **不要写 `datetime.now(timezone.utc)`**。MySQL 的 `DATETIME` 不存时区，代码传什么就存什么，
  而本机 MySQL 用本地时区（`SELECT NOW()` 返回北京时间），两边差 8 小时。
  实测：本地 22:27 提交问卷，接口返回的 `created_at` 是 14:27。
- 用统一入口 `now()` 的好处：以后要改口径（比如真部署到海外、改成 UTC + 时区），
  只改 `utils.py` 一个地方，不用满地找。
- 修复前写入的历史数据时间会偏 8 小时（只影响测试账号，已订正）。

### 其他约定

- 字段名一律用小写 + 下划线风格（`username`，禁止 `userName`）
- 后端端口固定 `5000`，前端端口固定 `5173`，前端请求一律走 `http://localhost:5000/api/...`
- `token` 由后端在注册/登录成功时生成，前端存起来，之后每次请求 `/api/me` 等接口时放在请求头里带来

> ✅ 当前进度：以上四个接口后端均已实现并通过实测（2026-09-26）。
>
> ➕ 补充（2026-09-29）：`PUT /api/me` 修改个人资料，为前端个人中心「保存修改」新增。
> - 只允许改 `name / major / grade`，**不允许改 username 和密码**
> - 未登录 → 401；`name` 为空 → 1001
> - 返回更新后的完整资料，前端可直接刷新页面显示

### 新增接口清单

| 接口 | 方法 | 作用 | 需登录 | 归层 |
|------|------|------|:------:|:----:|
| `/api/questions` | GET | 获取问卷题目 | ❌ | 第一层 |
| `/api/answers` | POST | 提交问卷答案（重复提交覆盖） | ✅ | 第一层 |
| `/api/answers` | GET | 查询我的问卷结果 | ✅ | 第一层 |
| `/api/cases` | GET | 获取推荐案例（按方向/年级筛选） | ✅ | 第二层 |
| `/api/cases/<id>` | GET | 案例详情（含步骤） | ✅ | 第二层 |
| `/api/chat` | POST | 向大模型提问 | ✅ | 第三层 |

### 新增错误码（沿用 1001-1004 之后）

| code | 含义 |
|------|------|
| 1005 | 问卷未填写（用于 `/api/chat`，不用于 `GET /api/answers`） |
| 1006 | 问卷格式不对（选项值不在允许范围内） |
| 1007 | 提问太频繁（超过每日次数上限） |
| 2001 | 大模型服务异常 |

### 几条必须记住的设计

- **`/api/questions` 不需要登录**：题目是公开固定内容，无隐私。其余 5 个都跟「我的数据」或「消耗额度」有关，必须鉴权。
- **`options` 必须返回数组不是字符串**：数据库存的是 `'["考研","就业"]'`，后端读出来要 `json.loads` 再返回。
- **`GET /api/answers` 没填过不报错**：返回 `{filled: false, answer: null}`，用 `filled` 让前端决定跳不跳问卷页。
  1005 只用在「没填问卷就调 `/api/chat`」这种真正的错误场景。
- **`GET /api/cases` 必须有兜底**：精确匹配 `direction + grade` 无结果时，放宽为「只要 direction 对上」就返回，
  否则冷门方向页面会空着。默认参数取用户自己的问卷结果。
- **`POST /api/chat` 不能只转发问题**：必须把用户问卷结果拼进 System Prompt，
  这样「问同一句话、不同用户答案不同」——这才是「根据用户需求来对答如流」。
- **`user_id` 一律从 token 反查**，不接受前端传。所有业务表带 `user_id` 做数据隔离。

## 数据库说明

| 项 | 内容 |
|----|------|
| 正式方案 | MySQL 8.x，库名 `futurepath`，表名 `users` |
| 建表脚本 | `backend/init.sql`（**表结构以这个文件为准**） |
| 后端模型 | `backend/app/models/user.py`（SQLAlchemy） |
| 开发期兜底 | 未配置 `.env` 时后端自动使用 SQLite（`backend/instance/dev.db`） |

**为什么要兜底**：`.env` 不会提交到 Git（里面的密码不能进仓库），
组员 clone 下来没有配置文件。用 SQLite 兜底，任何人 clone 完都能直接跑起来。

**两处表结构必须保持一致**，改任何一处都要同步另一处：

| 字段 | MySQL (`init.sql`) | SQLAlchemy (`user.py`) |
|------|--------------------|------------------------|
| id | INT PK AUTO_INCREMENT | Integer, primary_key |
| username | VARCHAR(20) UNIQUE | String(20), unique, index |
| password_hash | VARCHAR(256) | String(256) |
| name | VARCHAR(64) | String(64) |
| major | VARCHAR(64) NOT NULL | String(64), NOT NULL |
| grade | VARCHAR(16) NOT NULL | String(16), NOT NULL |
| created_at | DATETIME NULL | DateTime，由后端写入 UTC |

> 想切到 MySQL：在 `backend/` 下建 `.env`，写入
> `DATABASE_URL=mysql+pymysql://root:你的密码@localhost:3306/futurepath?charset=utf8mb4`
> 然后重启后端。

## 本地怎么跑起来

### 前置：装依赖

```bash
# 后端
cd backend
pip install -r requirements.txt

# 前端
cd frontend
npm install
```

### ★ 关键一步：建前端环境文件

`frontend` 目录下新建文件 `.env`，内容一行：

```
VITE_USE_MOCK=false
```

**为什么必须建**：不建的话前端默认走 Mock 假数据 —— 页面看着能注册成功，但数据库里什么都没有。
改完**必须重启 `npm run dev`** 才生效（vite 不热更新配置文件）。

### 启动（两个终端）

```bash
# 终端 1：后端
cd backend
python run.py                 # 看到 Running on http://127.0.0.1:5000

# 终端 2：前端
cd frontend
npm run dev                   # 看到 Local: http://localhost:5173/
```

浏览器打开 <http://localhost:5173>，F12 控制台应显示：

```
[env] 当前模式：真实接口 /api
```

### 自检：验证联调是否正常

**三个终端都开着**，再开一个：

```bash
cd frontend
node tools/check-live.cjs
```

25 项全过 = 前后端联调没有断点。这个脚本会真注册一个带时间戳的账号，
所以只要能显示出来，就一定是真后端给的数据，不存在“mock 蒙对了”的情况。
