# 上线怎么搞（给不熟悉服务器的同学看的）

> 目标：把 FuturePath 放到一台云服务器上，别人用浏览器就能打开。
> 本文按"点鼠标为主、敲命令为辅"写，遇到 `代码块` 就是照抄回车。

## 当前线上地址

**http://47.113.201.145:8080** —— 已部署完成，可直接访问。

- 服务器：阿里云轻量 2 核 4G，B 同学购买，**2026-11-18 到期**（答辩后不用续）
- 没有域名、没做备案：直接用 `IP:8080` 访问，绕开大陆机房 80/443 的备案要求

### 买之前确认三件事

1. **镜像选「应用镜像 → BT-Panel」（也就是宝塔面板）**
   - 腾讯云那边叫「宝塔Linux面板」，阿里云叫「BT-Panel」，是同一个东西。
   - 要点「**应用镜像**」这个标签，别选「系统镜像」——系统镜像是一张干净的空系统，
     装 Nginx、装 Python 全靠敲命令，没必要给自己找事。
   - 版本下拉里如果只有一项（比如「BT-Panel 阿里云专享版 9.2.0」）就用默认的，
     **灰色不可选是正常的，只有一个版本**。
     "阿里云专享版"只是宝塔给阿里云做的定制版（内置镜像加速之类），功能一样，不用纠结。
2. **地域选离你近的**（广州/上海/北京都行），远处延迟高，演示时点一下要等。
3. **不买域名也能上线**：大陆机房的域名走 80/443 必须备案（要 2~3 周）。
   我们用 `http://公网IP:8080` 访问，**不用备案**。等以后真备案了再改。

### 万一买成了「系统镜像」（没有宝塔）

怎么判断：控制台实例卡片里「镜像」那一行写的是 `Alibaba Cloud Linux 3.x`
或 `Ubuntu 22.04` 这种系统名，而不是 `BT-Panel`，就是没装宝塔。

补救有两条路，**新机器上什么都没存，选第一条最快**：

**路线 1：重置成应用镜像（推荐，2 分钟）**

控制台 → 点进这台机 → 右上「重置系统」或「更多 → 重置系统」
→ 镜像类型选「**应用镜像**」→ 选 **BT-Panel** → 确认。

- 重置会**清空数据**，刚买的机器上本来什么都没有，零损失；
- 公网 IP **不会变**，放心；
- 重置过程中会要你确认，完成后 1~2 分钟就能用。

**路线 2：不重置，自己装宝塔（3~15 分钟）**

点实例右上角的「远程连接」（浏览器里直接开一个终端），用 root 登录后执行：

```bash
curl -sSO https://download.bt.cn/install/install_panel.sh && bash install_panel.sh
```

中途问 `Do you want to install Bt-Panel to the /www directory now?(y/n)` 就输 `y`。
跑完最后会打印出**面板地址、账号、密码**，把它抄下来（关掉窗口就找不回了）。

> 两条路的区别只是"面板是怎么装上去的"，装完以后完全一样。

## ★ 快速通道（推荐）：一个包 + 一条命令

不想一步步点就照这个来，全程 5 分钟：

1. 准备 `futurepath-online.zip`（0.6 MB）。它已经打包好：后端代码、**带种子数据的 dev.db**
   （9 道题 / 18 个案例）、前端构建产物 `dist/`、以及下面那个部署脚本。
2. 宝塔「文件」→ 进入 `/www/wwwroot/` → 新建目录 `futurepath` → 进去 →
   上传这个 zip → 右键「解压」（解压到当前目录）→ 确认里面有 `backend / dist / deploy` 三个文件夹。
3. 宝塔「终端」里粘贴这一行回车（**前面一定要带 `sudo`**：阿里云宝塔镜像的终端
   默认登录用户是 `admin`，不是 `root`，不加会报"需要 root 权限"）：

   ```bash
   sudo bash /www/wwwroot/futurepath/deploy/setup-server.sh
   ```

   > 「`No such file or directory`」= 文件没上传成功或解压到了别处，不是脚本坏了。
   > 先用 `sudo find /www -maxdepth 4 -name setup-server.sh` 确认它到底在哪。

4. 阿里云控制台 → 这台服务器 → 「防火墙」→ 添加规则 **TCP 8080**。
5. 浏览器打开 `http://公网IP:8080`。

脚本自动做完这些：找/装 Python 3.9+、建虚拟环境装依赖、生成 `backend/.env`（随机密钥）、
用 systemd 守护 gunicorn、装并配置 Nginx（监听 8080、`/api` 反代）、系统防火墙放行、最后自检。

可以重复跑，做过的步骤会跳过，不会覆盖已存在的 `.env`。

> 关于大模型：如果 `backend/.env` 里的 `LLM_API_KEY` 是空的，对话页会退化成"演示模式"
> （固定文案）。填上自己的 key 后执行 `sudo systemctl restart futurepath` 就是真回答了。

下面是**手动版**，想知道每一步到底在干什么、或者脚本某步失败要单独补的时候看。

## 二、服务器上要装什么

买完等 1~2 分钟初始化，然后去控制台拿面板账号：

- **阿里云**：控制台 → 轻量应用服务器 → 点进这台机 → 「应用详情」→「查看面板信息」，

丢了会提示"面板入口不正确"。

浏览器打开那个地址登录。第一次进去可能弹"推荐安装套件"，**关掉就行**，我们自己挑要装的东西。

然后做 3 件事：

1. **软件商店** → 安装 **Nginx**（选"极速安装"就行）。
2. **软件商店** → 搜索并安装 **Python项目管理器**（有的版本叫「Python项目」）。
3. **安全**（左侧菜单）→ 放行端口 **8080**。
   （另外去云控制台的「防火墙」里也加一条 TCP 8080 —— 阿里云在
   轻量服务器详情页的「防火墙」标签，腾讯云在「防火墙」页。

## 四、把后端跑起来

### 1. 建虚拟环境、装依赖

宝塔「终端」（左侧菜单里）打开命令行，依次执行：

```bash
cd /www/wwwroot/futurepath/backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements-prod.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

> `requirements-prod.txt` 比 `requirements.txt` 多一个 gunicorn。
> 为什么不合并？因为 gunicorn 只能在 Linux 上跑，组员本地都是 Windows，
> 混在一起他们一装就报错。

### 2. 写配置文件 `.env`

`backend/.env.example` 是模板，复制一份改名 `.env`，然后改这几个值：

| 变量 | 填什么 |
|---|---|
| `DATABASE_URL` | **用 SQLite 就把这一行删掉**（不要写成空值，空值会报错） |
| `SECRET_KEY` | 换成一串随机字符：`python3 -c "import secrets;print(secrets.token_hex(32))"` |
| `FLASK_DEBUG` | **不要写**（写了就是给黑客开后门） |
| `LLM_API_KEY` | 填你智谱的 key（只填在这台服务器上，别提交到 Git） |
| `LLM_DAILY_LIMIT` | **不要写**，保持默认 20 次/天 |

> ⚠️ 公网上**千万别**设 `LLM_DAILY_LIMIT=0`。那个开关是给本机调试的，
> 挂到公网就是"任何人来刷你的 key 余额"。

### 3. 数据从哪来

服务器上第一次启动会自动建一个**空库**，题目和案例全是 0 条，页面看着像坏了。

**最省事的做法**：把你自己电脑上已经灌好数据的那个文件
`backend/instance/dev.db` 直接上传到服务器的 `backend/instance/` 目录下。
里面有 9 道题、18 个案例，还有你本机那几个测试账号，传上去立刻就能用。

（想从零建也行：服务器装 MySQL，导入 `backend/init.sql`，再把 `.env` 里的
`DATABASE_URL` 填上。课程演示没必要，多养一个数据库只会多一个出错的地方。）

### 4. 用 gunicorn 启动

宝塔「Python项目管理器」→ 添加项目：

| 项 | 填什么 |
|---|---|
| 项目路径 | `/www/wwwroot/futurepath/backend` |
| Python 版本 | 3.11 或以上（我们本地是 3.13） |
| 框架 | 其他 / Flask |
| 启动方式 | `gunicorn` |
| 启动文件/命令 | `gunicorn -c ../deploy/gunicorn.conf.py run:app` |
| 端口 | `5000` |
| 是否安装依赖 | 否（上面已经装过了） |

点启动，看到状态是"运行中"就对了。

> ⚠️ **绝对不要用 `python run.py` 上线**。那是开发服务器，单线程，
> 而且一旦有人把 host 改成 `0.0.0.0`，调试器就暴露在公网上了。

## 五、把前端放上去

前端在我们自己电脑上打包，只把打包结果传上去就行（服务器不用装 Node）。

### 1. 在自己电脑上打包

```bash
cd D:\Code\FuturePath\frontend
npm run build
```

跑完会多出一个 `dist` 文件夹。

> 打包时 Vite 会自动读 `frontend/.env.production`，里面已经把
> `VITE_USE_MOCK` 钉成 `false`。**这一步很重要**：不钉死的话，
> 前端会一直用假数据，页面能点、但一条真实请求都没发出去，很难发现。

### 2. 上传

把 `dist` 整个文件夹传到服务器的 `/www/wwwroot/futurepath/` 下，变成：

```
/www/wwwroot/futurepath/dist/index.html
/www/wwwroot/futurepath/dist/assets/...
```

## 六、配 Nginx

宝塔「网站」→ 添加站点：

- 域名：**不填**（没有域名），或者填服务器公网 IP
- 根目录：`/www/wwwroot/futurepath`
- PHP 版本：**纯静态**

建好后点站点名 → 「配置文件」，把整个 `server { }` 换成
仓库里 `deploy/nginx-futurepath.conf` 的内容，保存。

**注意**：那份配置里 `root` 写的是 `/www/wwwroot/futurepath/dist`，
如果你的 `dist` 传到别的地方，要把这一行改成实际路径。

保存后 Nginx 会自动重载，没有报错就成功了。

## 八、出问题怎么查

| 现象 | 大概率原因 | 怎么办 |
|---|---|---|
| 打开是 502 Bad Gateway | 后端没起来 | Python项目管理器里看项目状态；点「日志」看报错 |
| 页面能开，但列表全是 0 条 | 数据库是空的 | 上传本机 `instance/dev.db`（见四.3） |
| 页面能点，但全是假数据 | 打包时没用 `.env.production` | 确认该文件在，重新 `npm run build` 再传 |
| 转圈很久然后报错 | AI 请求超时 | 检查 `gunicorn.conf.py` 里 `timeout = 75` 是否生效 |
| 用一会儿就掉登录 | 起了多个 worker | `workers` 必须是 **1**，理由见配置文件注释 |
| 8080 打不开 | 端口没放行 | 宝塔「安全」和云控制台「防火墙」两边都要放行 |
| 提示要备案 | 用了域名 + 80 端口 | 换回 `IP:8080`，或去备案 |
| 脚本停在 5/6，报 `All matches were filtered out by exclude filtering for argument: nginx` | 系统的 dnf 仓库把 nginx 过滤掉了（不是没这个包） | 宝塔「软件商店」搜 **Nginx** 点安装，装完**重跑脚本**——脚本会自动改用宝塔自带的 nginx |
| 重跑脚本报 `nginx -t` 失败，`open() "/var/log/nginx/..." failed` | 用宝塔 nginx 时日志目录不存在 | 先 `sudo mkdir -p /var/log/nginx` 再重跑（新版脚本已自动改用 `/www/wwwlogs`） |

## 九、上线后要守住的几条

1. **`.env` 永远不进 Git**（仓库是公开的，key 泄露会在几小时内被人刷爆）。
2. **`FLASK_DEBUG` 不要设 1**，调试器能在浏览器里执行任意代码。
3. **每日 20 次上限保持默认**，那是防刷的闸门，不是缺点。
4. **定期备份 `backend/instance/dev.db`**（宝塔「计划任务」可以设每天打包一次）。
5. **宝塔面板本身**：改掉默认端口 8888、用强密码、别用面板默认账号名。
6. **重启后端 = 所有人都要重新登录**（token 存在进程内存里，这是目前的设计，
   以后要做大就得换成 Redis 或数据库表）。

## 十、这份配置里几个"为什么"

- **为什么 workers 只能是 1**：登录 token 存在 Python 进程的内存里。开两个 worker
  就是两个互不相通的进程，在 A 登录的 token 到 B 就查不到，用户会"时好时坏地掉登录"。
  靠 `threads = 8` 扛并发，因为线程之间共享内存。
- **为什么 Nginx 用 8080**：大陆机房域名走 80 必须备案。用 IP + 非 80 端口绕开，
  课程演示完全够。以后备案了改一行就行。
- **为什么不用配"路由回退"**：我们用的是 hash 路由（地址带 `#`），
  服务器只需要返回 `index.html`，`/cases` 这种路径根本不会发给服务器。
  `try_files` 那行是留着防以后改成 history 路由的，不影响现在。
- **为什么接口不用改地址**：前端所有请求都发 `/api/xxx`，Nginx 把 `/api` 转给后端。
  对浏览器来说前后端是同一个域名，**跨域问题自然就没了**。
